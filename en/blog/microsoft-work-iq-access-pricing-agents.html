Microsoft Work IQ: what it is, how agents access it, and what you pay

Work IQ is the intelligence layer behind Microsoft 365 Copilot. Understand its eight building blocks, the different ways agents can access it, and where Copilot Credits may apply.

Microsoft 365By MC3 Cloud Team27 October 2026

Microsoft presents Work IQ as the intelligence layer that helps Copilot and agents understand organisational content, permissions and working context. The important point is that Work IQ is not a single product or database. It combines knowledge retrieval, permission-aware grounding, agent access controls and usage metering.

For customers and partners, the practical question is therefore not only what Work IQ can do, but also how an agent reaches it. That architectural choice affects capabilities, governance and cost.

Work IQ in plain English

Work IQ can be understood as eight connected building blocks.

  1. Semantic index: organises Microsoft 365 content so information can be found by meaning, not only by exact keywords.
  2. Permission-aware grounding: returns only information that the person making the request is already authorised to access.
  3. Context: searches, evaluates and assembles the information required to ground an answer.
  4. Work IQ API: provides a direct entry point for applications and agents outside the native Copilot experience.
  5. Policy engine: checks each request against identity, permissions and administrative controls. Write operations are disabled by default.
  6. Tools: exposes common actions such as fetching, creating or updating information through a consistent vocabulary.
  7. Workspaces: gives long-running agents a place inside the customer tenant to retain working material between steps.
  8. Usage-based billing: meters calls and research activity when Work IQ is consumed through chargeable agent scenarios.

The first three elements form the research capability already used by Copilot. The remaining elements make that capability accessible to a wider range of agents and applications, while adding policy and commercial controls.

The access route determines the experience

The same organisational knowledge can be reached through several agent-building surfaces. They should not be treated as equivalent.

Agent Builder

Agent Builder runs inside Microsoft 365 Copilot. It is designed for lightweight question-and-answer experiences for an individual or a small team.

The agent reaches Work IQ natively. The experience is included in the Microsoft 365 Copilot licence, and the builder does not expose the broader action and orchestration capabilities available in Copilot Studio.

Copilot Chat agents

Agents can extend Microsoft 365 Copilot Chat with company knowledge. Microsoft manages the interaction and the planning experience remains close to Copilot Chat.

For licensed users working through Microsoft channels, usage can fall within the applicable fair-use model. Unlicensed usage may consume Copilot Credits.

Standard Copilot Studio agents

A standard Copilot Studio agent follows a flow designed in advance. Access to Microsoft 365 services is provided through separate capabilities such as connectors and MCP servers for Mail, Calendar, Teams, SharePoint, OneDrive or other services.

In this model, Work IQ is not automatically the route used to reach organisational data. The agent maker controls the sequence of actions and the sources called at each step.

GitHub Copilot-style autonomous agents

In the GitHub Copilot harness described in the source material, the agent determines its own steps at runtime. Work IQ can be added as an optional tool, creating one broad entry point to organisational knowledge.

This offers more flexibility, but the harness consumes credits and Work IQ usage is billed separately when the tool is called.

Direct API access

Developers can also call the Work IQ API directly from their own applications or agent frameworks. In this scenario, usage is metered independently of the Microsoft 365 Copilot licences already assigned in the tenant.

What actually creates a Work IQ charge?

The key distinction is between using Copilot and calling the Work IQ API.

According to the material supplied, building a standard Copilot Studio agent does not by itself trigger the Work IQ meter. Adding Mail, Calendar or Teams capabilities through their dedicated tools does not automatically trigger it either.

A Work IQ charge begins when the agent calls the Work IQ API, either directly or through a harness where the Work IQ tool has been enabled.

The supplied pricing information identifies two components:

  • Tools: 0.1 Copilot Credit per call, at a flat rate.
  • Chat and Context: variable usage, with no published unit rate in the supplied material.

This second component is the main planning constraint. If the rate for the research activity is not published, organisations cannot reliably forecast the complete cost of a high-volume autonomous agent from the tool-call price alone.

Two meters need two controls

Copilot Studio usage and Work IQ usage should be treated as two separate cost areas.

Copilot Studio credits are governed through Power Platform administration. Work IQ requires its own spending policy in the Microsoft 365 admin environment. Limiting one meter does not automatically limit the other.

For a production deployment, partners should therefore validate both controls:

  • the credit budget assigned to the agent or environment;
  • the spending policy applied to Work IQ API consumption.

This is especially important for autonomous agents. A human asks a limited number of questions during the working day. An unattended process can generate requests continuously, which changes the economics of the solution.

Governance points to explain before deployment

Work IQ can retrieve information according to the requesting identity and the permissions already present in Microsoft 365. This does not remove the need for governance.

Three controls deserve particular attention:

  • Write access: creation, update and deletion are disabled by default and must be enabled administratively.
  • Tenant boundaries: calls are associated with a tenant and a signed-in identity rather than operating anonymously.
  • Permission quality: permission-aware retrieval reflects the access model already configured. Excessive SharePoint, Teams or file permissions remain excessive permissions.

Work IQ should therefore be introduced alongside a review of identity, data access and agent spending policies, not as a standalone AI feature.

How to guide a customer

Start with the operating model rather than the technology name.

  • Choose Agent Builder for a lightweight knowledge assistant inside Microsoft 365 Copilot.
  • Choose Copilot Chat when the objective is to extend the Microsoft chat experience with company knowledge.
  • Choose a standard Copilot Studio agent when the process can be designed explicitly and each action should be controlled in advance.
  • Choose an autonomous harness with Work IQ when the agent must decide dynamically what to research and which steps to take.
  • Choose direct API access when Work IQ must be embedded into a custom application or an external agent framework.

The more autonomy and flexibility the customer requires, the more important cost controls, permissions and auditability become.

The point to remember

Work IQ is one intelligence capability exposed through several different doors. The knowledge and permission model may be shared, but the commercial model is not.

Before positioning an agent, confirm three things: where it will be built, how it will reach Microsoft 365 data, and which usage meter will apply. That is the difference between a useful proof of concept and a production service with predictable governance and cost.
