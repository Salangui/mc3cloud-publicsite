BullWall — Ransomware Containment and Server Protection

Add automated ransomware containment to protect your customers’ data, complement their existing security and prepare for recovery after an incident.

Add containment alongside prevention

Your customers already have security controls in place. But what response is ready if ransomware still manages to start encrypting their data?

BullWall Ransomware Containment addresses this stage: it monitors activity at the data layer, detects malicious encryption and automatically initiates containment actions. The aim is to limit the spread and the number of affected files while giving IT and security teams the evidence they need to investigate.

This approach complements existing protection. It does not replace antivirus, EDR/XDR, backups or a disaster recovery plan.

Ransomware Containment: detect and respond at the data layer

Ransomware Containment is the core of the BullWall portfolio. The vendor describes monitoring that combines 28 sensors and machine learning to distinguish legitimate activity from ransomware behaviour.

BullWall lists coverage for:

  • servers and file systems;
  • file shares;
  • SAN and NAS storage infrastructure;
  • cloud file systems;
  • Active Directory;
  • SharePoint Online and OneDrive.

When malicious encryption is identified, the solution enriches the alert with user, device and file context, then assesses the severity and confidence of the detection.

Move from detection to automated containment

BullWall describes a coordinated response sequence that can:

  • isolate the compromised user;
  • revoke sessions and access permissions;
  • disable the compromised account;
  • limit lateral movement;
  • coordinate actions across identities, endpoints and file systems.

BullWall states that the time from first detection to containment is under one second, with 24/7 automated response. These are vendor-stated capabilities, not an SLA or a monitoring service provided by MC3 Cloud.

Each event is logged. Teams receive structured alerts and a forensic timeline to understand the incident and the actions taken.

Prepare for recovery without replacing backups

Containment and restoration address two different needs: limiting the attack, then returning systems and data to operation.

In the process described by BullWall, recovery preparation includes:

  • verifying backup integrity;
  • searching the network for indicators of compromise;
  • checking endpoint health;
  • verifying network connectivity before clearing restoration.

For resellers and MSPs, this positions BullWall as an additional layer alongside backup and disaster recovery investments, rather than a replacement for them.

Server Intrusion Protection: intervene before encryption

Server Intrusion Protection addresses an earlier stage: attempts to gain unauthorised server access, including through stolen credentials or hijacked RDP sessions.

The solution aims to detect and block these intrusions, prevent attackers from disabling security tools and limit lateral movement. It also maintains access logs for investigation.

For this offering, BullWall states 24/7 automated remediation and a response time of under one second from detection to containment. These are vendor-stated capabilities, not a service commitment from MC3 Cloud.

Virtual Server Protection: secure the VMware layer

Virtual Server Protection addresses threats targeting VMware vSphere and ESXi infrastructure. Installed directly on ESXi hosts, the solution provides:

  • multifactor authentication for every SSH login;
  • monitoring of processes, datastores, virtual disks, NFS storage and internal storage;
  • detection of encryption attempts and malicious activity;
  • 24/7 automated response;
  • immutable access logs for investigation and audits.

This offering complements Ransomware Containment by specifically addressing virtual infrastructure.

Document incidents and response actions

BullWall describes automated reports with supporting evidence mapped to GDPR, NIS2, DORA and cyber insurance requirements.

These records can support audits and help demonstrate the measures taken. They do not constitute a guarantee of regulatory compliance or acceptance by an insurer.
