Microsoft Work IQ : comment Copilot comprend votre environnement de travail

Comprenez comment Work IQ aide Copilot à exploiter le contexte Microsoft 365, ses différences avec un connecteur, ses limites et son modèle de consommation.

Microsoft 365Par Aslam Gangat27 octobre 2026

Deux assistants d’intelligence artificielle peuvent accéder à un document SharePoint sans disposer de la même compréhension de votre environnement de travail.

L’un peut être connecté à une ou plusieurs sources précises. L’autre peut s’appuyer sur une couche capable de mobiliser les données, les relations et les outils présents dans Microsoft 365. C’est le rôle de Work IQ.

Dans cet article, nous allons expliquer ce qu’est Work IQ, ce qui le distingue de Microsoft Graph et d’un simple connecteur, et pourquoi son intégration à Microsoft 365 Copilot peut être pertinente. Nous aborderons également ses limites, la sécurité des données et la possibilité d’utiliser Work IQ en dehors de Copilot avec une facturation à la consommation.

À la fin de votre lecture, vous saurez distinguer trois éléments souvent confondus : le modèle d’intelligence artificielle, l’accès aux données et la construction du contexte professionnel. Vous pourrez ainsi comparer plus justement les différentes façons de connecter une intelligence artificielle à Microsoft 365.

Qu’est-ce que Work IQ ?

Work IQ est la couche d’intelligence du travail utilisée par Microsoft pour aider Copilot et certains agents à exploiter le contexte professionnel d’un utilisateur.

Son rôle ne consiste pas seulement à rechercher un mot dans un fichier. Work IQ aide l’agent à mobiliser les informations et les relations pertinentes parmi les messages, documents, réunions, personnes, projets et outils auxquels l’utilisateur est autorisé à accéder.

Microsoft présente Work IQ autour de quatre composantes :

  • la conversation, pour interagir avec l’utilisateur ou entre agents ;
  • le contexte, pour préparer les informations utiles à la demande ;
  • les outils, pour rechercher des informations ou effectuer des actions ;
  • les espaces de travail, pour conserver le contexte de tâches plus longues.

Work IQ n’est donc ni un modèle d’intelligence artificielle ni une nouvelle base de données. Le modèle analyse la demande et produit la réponse. Work IQ lui apporte le contexte professionnel et les outils nécessaires.

Work IQ n’est pas Microsoft Graph

Microsoft Graph fournit aux applications des interfaces leur permettant d’accéder aux données et aux services Microsoft 365, selon les autorisations accordées.

Une application peut, par exemple, utiliser Microsoft Graph pour rechercher un message, consulter un calendrier ou ouvrir un document. Elle doit ensuite déterminer comment exploiter et rapprocher les informations obtenues.

Work IQ intervient à un autre niveau. Il prépare un contexte adapté à Copilot ou à un agent et l’aide à mobiliser les données et les outils utiles pour accomplir une tâche.

La différence peut se résumer ainsi :

Microsoft Graph donne accès aux ressources. Work IQ aide un agent à mobiliser les ressources pertinentes dans le contexte du travail de l’utilisateur.

Les deux ne s’opposent pas. Work IQ s’inscrit dans l’écosystème Microsoft 365 et s’appuie sur ses données, ses services, ses identités et ses autorisations.

Un connecteur Microsoft 365 ne donne pas automatiquement accès à Work IQ

D’autres solutions d’intelligence artificielle peuvent accéder à certaines données Microsoft 365 au moyen de connexions autorisées.

Il serait donc incorrect d’affirmer que seul Microsoft 365 Copilot peut consulter un fichier SharePoint, rechercher un message Outlook ou exploiter une information stockée dans OneDrive.

La différence se trouve dans la manière dont l’assistant construit son contexte.

Un connecteur donne accès à une source déterminée. Work IQ vise à créer une compréhension plus large du travail en rapprochant les données, les personnes, les relations et les outils disponibles dans l’environnement Microsoft 365.

Pour comparer plusieurs solutions, il ne suffit donc pas de vérifier si elles peuvent se connecter à SharePoint ou Outlook. Il faut également examiner :

  • les sources réellement accessibles ;
  • les autorisations demandées ;
  • la manière dont les informations provenant de plusieurs services sont rapprochées ;
  • les actions que l’assistant peut effectuer ;
  • les contrôles administratifs disponibles ;
  • l’environnement dans lequel les données sont traitées.

Un exemple : préparer un rendez-vous client

Imaginons cette demande :

« Prépare-moi pour ma réunion avec ce client. Résume les échanges récents, retrouve la proposition commerciale et identifie les actions encore ouvertes. »

Les informations nécessaires peuvent être réparties entre Outlook, le calendrier, Teams, SharePoint et OneDrive.

Avec une connexion limitée à SharePoint

L’assistant peut retrouver la proposition commerciale et les documents accessibles à l’utilisateur.

Il ne dispose cependant pas nécessairement des messages Outlook, de la prochaine réunion ou des conversations Teams si ces sources ne sont pas également connectées et autorisées.

Cette limite ne vient pas forcément du modèle d’intelligence artificielle. Elle vient du périmètre des données auquel il peut accéder.

Avec plusieurs connecteurs

Une autre intelligence artificielle peut disposer de connexions distinctes à SharePoint, Outlook, OneDrive et Teams.

Son périmètre est alors plus large. Il reste toutefois nécessaire de comprendre comment elle rapproche les résultats, quelles informations sont transmises à sa plateforme et quelles règles de sécurité, de conservation et de traitement s’appliquent.

Avec Microsoft 365 Copilot et Work IQ

Work IQ vise à construire un contexte couvrant les données, les personnes, les relations et les outils disponibles dans Microsoft 365.

L’objectif n’est donc pas seulement de retrouver davantage de documents. Il s’agit de fournir à Copilot un contexte professionnel cohérent pour répondre à une demande qui couvre plusieurs dimensions du travail.

Cela ne garantit pas que chaque réponse sera complète ou exacte. Le résultat dépend toujours de la disponibilité des informations, de leur qualité, de leur emplacement et des autorisations de l’utilisateur.

Des données traitées dans le prolongement de Microsoft 365

Microsoft 365 Copilot n’a pas besoin de créer un référentiel séparé contenant les données de l’entreprise. Avec Work IQ, il exploite les informations déjà présentes dans Exchange Online, SharePoint, OneDrive ou Teams, en respectant les droits de l’utilisateur et les politiques de l’organisation.

Les données restent ainsi placées sous le cadre de protection de Microsoft 365 : identité Microsoft Entra, autorisations, étiquettes de confidentialité, politiques de conservation et audit.

Microsoft indique également que les requêtes, les réponses et les données accessibles par Microsoft Graph ne sont pas utilisées pour entraîner les modèles de fondation.

Lorsqu’une intelligence artificielle externe se connecte à Microsoft 365, elle doit recevoir les données ou les extraits nécessaires dans son propre environnement pour pouvoir les analyser. Les documents d’origine peuvent rester dans Microsoft 365, mais les informations utilisées pour produire la réponse sont alors traitées par une plateforme supplémentaire.

Cette plateforme peut disposer de ses propres garanties de sécurité et de résidence. Elle introduit néanmoins une nouvelle chaîne de traitement qu’il faut évaluer :

  • les permissions accordées au connecteur ;
  • les données transmises ;
  • la région de traitement ;
  • la durée de conservation ;
  • les sous-traitants impliqués ;
  • les garanties contractuelles applicables.

Avec Copilot et Work IQ, l’intelligence artificielle exploite le contexte dans le prolongement de l’environnement Microsoft 365. Avec une intelligence artificielle tierce, les données utiles doivent être transmises à un autre environnement de traitement. Cette différence réduit le nombre de frontières techniques, contractuelles et organisationnelles que l’entreprise doit gouverner.

Peut-on utiliser Work IQ en dehors de Copilot ?

Oui. Microsoft fournit des API et des protocoles permettant à une application ou à un agent d’utiliser les capacités de Work IQ en dehors de l’interface standard de Microsoft 365 Copilot.

Cette approche peut être pertinente pour créer :

  • un agent spécialisé ;
  • une interface métier personnalisée ;
  • une application combinant Work IQ avec d’autres services ;
  • un processus nécessitant des actions dans Microsoft 365.

Microsoft propose notamment des interfaces Agent-to-Agent, Model Context Protocol et REST. Elles permettent à différents agents et environnements applicatifs d’utiliser Work IQ tout en conservant les autorisations et les contrôles de gouvernance associés à Microsoft 365.

Consulter la documentation des API Work IQ (s’ouvre dans un nouvel onglet)

Cet accès externe n’est toutefois pas automatiquement couvert par une licence Microsoft 365 Copilot.

L’utilisation des API Work IQ est indépendante de la licence Microsoft 365 Copilot et repose sur une facturation liée à l’usage. Selon l’expérience concernée et le modèle commercial applicable, cette consommation peut être suivie au moyen de Copilot Credits.

Il faut donc distinguer :

  • Work IQ intégré à Microsoft 365 Copilot, dans le cadre de la licence et de l’expérience concernées ;
  • Work IQ utilisé comme service par une application ou un agent, avec une consommation et des coûts à surveiller.

Avant un déploiement, l’entreprise doit vérifier l’expérience utilisée, les outils appelés, les licences nécessaires et le modèle de consommation applicable.

Work IQ ne corrige pas les problèmes de gouvernance

Work IQ ne contourne pas les autorisations Microsoft 365.

Deux utilisateurs peuvent recevoir des réponses différentes parce qu’ils n’ont pas accès aux mêmes messages, fichiers, sites ou réunions.

Cette protection ne résout cependant pas les partages excessifs. Si un document SharePoint est accessible à un public trop large, Copilot peut le rendre plus facile à découvrir pour les utilisateurs qui disposent déjà de cet accès.

Avant un déploiement étendu, il convient donc de revoir :

  • les autorisations SharePoint et OneDrive ;
  • les liens de partage et les accès externes ;
  • les groupes ou droits devenus obsolètes ;
  • les applications autorisées dans Microsoft Entra ;
  • les données sensibles accessibles trop largement ;
  • les actions confiées aux agents ;
  • le suivi des consommations facturées à l’usage.

La qualité des données compte également. Work IQ ne peut pas corriger automatiquement des documents obsolètes, des procédures contradictoires ou une information absente de Microsoft 365.

Préparer Microsoft 365 avant de déployer Copilot

Activer des licences ne suffit pas pour réussir un projet Copilot.

Il faut d’abord comprendre quelles informations seront accessibles, vérifier les pratiques de partage, sélectionner des cas d’usage adaptés et préparer les utilisateurs à exploiter et vérifier les réponses produites par l’intelligence artificielle.

Le service managé Préparation et adoption de Microsoft 365 Copilot de MC3 Cloud accompagne cette démarche. Il aide l’organisation à aborder la préparation de son environnement Microsoft 365 et l’adoption de Copilot de manière structurée.

Cette approche permet de traiter deux dimensions souvent séparées : la préparation technique de Microsoft 365 et l’intégration de Copilot dans le travail quotidien.

Les questions à poser avant de choisir

Avant de connecter une intelligence artificielle à Microsoft 365, posez-vous les questions suivantes :

  1. Quelles données l’intelligence artificielle doit-elle utiliser ?
  2. Ces données se trouvent-elles dans une seule application ou sont-elles réparties dans Microsoft 365 ?
  3. L’assistant doit-il seulement retrouver des documents ou reconstruire un contexte entre plusieurs services ?
  4. Quelles autorisations seront accordées au connecteur ou à l’agent ?
  5. Dans quel environnement les données seront-elles traitées ?
  6. L’assistant doit-il uniquement répondre ou également effectuer des actions ?
  7. Work IQ sera-t-il utilisé dans Copilot ou consommé par une application externe ?
  8. Quelle licence ou quel modèle de consommation s’applique ?
  9. Comment les accès, les usages et les coûts seront-ils contrôlés ?
  10. L’environnement Microsoft 365 est-il suffisamment préparé et sécurisé ?

Ce qu’il faut retenir

Work IQ n’est ni un modèle d’intelligence artificielle, ni une base de données, ni un nouveau nom donné à Microsoft Graph.

C’est la couche d’intelligence du travail qui aide Copilot et certains agents à mobiliser les données, les relations et les outils professionnels auxquels un utilisateur est autorisé à accéder.

D’autres assistants peuvent également se connecter à Microsoft 365. La comparaison doit donc porter sur la profondeur de l’intégration, la construction du contexte, les autorisations, la gouvernance et l’environnement de traitement, et non uniquement sur le modèle utilisé.

Work IQ peut aussi être utilisé en dehors de Microsoft 365 Copilot par une application ou un agent. Cet accès repose alors sur une facturation à la consommation et doit être suivi comme tel.

La question finale est simple :

Votre assistant doit-il seulement consulter quelques sources Microsoft 365, ou doit-il comprendre et mobiliser un contexte de travail réparti dans l’ensemble de votre environnement ?

C’est cette distinction qui permet d’évaluer la forme d’intégration la plus adaptée aux données, aux usages et aux exigences de gouvernance de votre organisation.
