Microsoft Work IQ : comprendre les agents, les accès aux données et les Copilot Credits

Work IQ aide Microsoft 365 Copilot et les agents à comprendre le contexte de travail. Découvrez comment les agents exploitent les données Microsoft 365 et dans quels cas des Copilot Credits peuvent être consommés.

Microsoft 365Par Équipe MC3 Cloud28 octobre 2026

Deux agents peuvent répondre à la même question à partir des données de l’entreprise, tout en utilisant des architectures et des modèles de consommation différents.

L’un peut fonctionner directement dans Microsoft 365 Copilot. L’autre peut être exécuté dans Copilot Studio ou dans une application développée sur mesure.

Pour l’utilisateur, le résultat peut sembler similaire. En arrière-plan, la manière d’accéder aux données, les outils utilisés et le modèle de consommation peuvent pourtant être très différents.

Pour comprendre ces différences, il faut distinguer les données Microsoft 365, les mécanismes permettant d’y accéder et la couche d’intelligence Work IQ.

Work IQ, c’est quoi ?

Work IQ est la couche d’intelligence qui aide Microsoft 365 Copilot et les agents à comprendre le contexte de travail d’un utilisateur.

Elle s’appuie sur les informations disponibles dans Microsoft 365 et les applications connectées, notamment les e-mails, fichiers, conversations, réunions, personnes et projets, afin de fournir à Copilot et aux agents un contexte pertinent.

Work IQ s’articule autour de trois dimensions :

  • les données, issues de Microsoft 365 et des applications connectées ;
  • la mémoire, qui apporte du contexte sur l’utilisateur et son travail ;
  • l’inférence, qui permet de raisonner sur ce contexte et d’utiliser les outils disponibles.

Work IQ ne doit donc pas être confondu avec Microsoft Graph.

Microsoft Graph permet aux applications d’accéder aux données et relations de Microsoft 365 à travers des API. Work IQ va plus loin en exploitant le contexte du travail pour permettre à Copilot et aux agents de raisonner et d'utiliser les bons outils.

Work IQ ne donne pas accès à toutes les données

Work IQ ne contourne pas les permissions Microsoft 365.

Lorsqu’un agent agit dans le contexte d’un utilisateur, les informations auxquelles il peut accéder dépendent des autorisations de cet utilisateur.

Deux collaborateurs peuvent donc poser la même question à un agent et obtenir des réponses différentes selon leurs accès et leur contexte professionnel.

C’est un point important en matière de gouvernance : Copilot et les agents peuvent rendre beaucoup plus facile la découverte d’informations auxquelles un utilisateur avait déjà accès.

Des sites SharePoint trop ouverts, des fichiers mal partagés ou des permissions devenues obsolètes doivent donc être traités avant de déployer largement Copilot et les agents.

Tous les agents n’accèdent pas aux données de la même manière

Un agent peut exploiter les informations de Microsoft 365 de plusieurs façons :

  • Work IQ intégré à Microsoft 365 Copilot ;
  • des sources de connaissances comme SharePoint ;
  • des Copilot connectors ;
  • des outils associés à Outlook, Teams, OneDrive, SharePoint ou Calendar ;
  • Microsoft Graph ;
  • des connecteurs Power Platform ;
  • les API et outils Work IQ ;
  • des API métier ou des services externes.

Ces approches ne sont pas équivalentes et peuvent être combinées.

Par exemple, le simple fait qu’un agent consulte des documents SharePoint ne signifie pas nécessairement qu’il appelle une API Work IQ.

C’est pour cette raison que deux agents donnant une impression similaire à l’utilisateur peuvent avoir des architectures très différentes.

Agent Builder : créer rapidement un agent dans Microsoft Copilot

Agent Builder permet de créer simplement un agent déclaratif depuis Microsoft Copilot.

Le créateur définit les instructions de l’agent et les sources de connaissances qu’il peut utiliser, par exemple des sites SharePoint ou des informations accessibles à travers des Copilot connectors.

Cette approche est particulièrement adaptée à des scénarios internes simples :

  • répondre à partir de procédures commerciales ;
  • accompagner l’onboarding d’une équipe ;
  • retrouver des informations dans une base documentaire ;
  • fournir des réponses basées sur un ensemble défini de connaissances internes ;
  • appliquer des consignes propres à l’entreprise.

Pour un utilisateur disposant d’une licence Microsoft 365 Copilot, l’utilisation de ces agents dans Microsoft Copilot peut être couverte par cette licence selon les capacités utilisées.

Les conditions peuvent être différentes pour les utilisateurs sans licence Microsoft 365 Copilot, notamment lorsqu’un agent exploite des données partagées de l’organisation.

Agent Builder reste volontairement simple. Lorsqu’un scénario nécessite davantage d’actions, de connecteurs ou de workflows, l’agent peut être repris dans Copilot Studio.

Copilot Studio : plusieurs architectures sont possibles

Copilot Studio permet d’aller plus loin en combinant connaissances, outils, connecteurs, workflows et différents canaux de publication.

Mais tous les agents Copilot Studio ne fonctionnent pas de la même manière.

Un agent peut utiliser des outils propres à certains services Microsoft 365, comme Mail, Teams, SharePoint ou OneDrive.

Il peut également utiliser Work IQ afin d'exploiter le contexte fourni par plusieurs services Microsoft 365.

Dans la nouvelle expérience Copilot Studio reposant sur le GitHub Copilot harness, Work IQ peut être utilisé par les agents concernés. Cette architecture utilise une facturation à la consommation en Copilot Credits.

D’autres outils Microsoft 365 restent disponibles dans des architectures reposant sur le standard harness, avec un runtime et un modèle de consommation différents.

Il ne suffit donc pas de savoir qu’un agent a été créé dans Copilot Studio. Il faut également comprendre quels outils il utilise et comment il est exécuté.

Un agent autonome n’est pas forcément un agent Work IQ

L’autonomie d’un agent et son accès à Work IQ sont deux sujets différents.

Un agent autonome peut accomplir certaines tâches avec moins d’intervention humaine en fonction de ses instructions, de ses déclencheurs et des outils mis à sa disposition.

Il peut par exemple utiliser :

  • Work IQ ;
  • des connecteurs Power Platform ;
  • Microsoft Graph ;
  • Dataverse ;
  • des API métier ;
  • des workflows ;
  • ou plusieurs de ces composants.

Utiliser Work IQ ne rend donc pas automatiquement un agent autonome. Et un agent autonome n’a pas nécessairement besoin de Work IQ.

L’autonomie peut cependant avoir un impact sur la consommation si l’agent exécute de nombreuses opérations, appelle plusieurs outils ou utilise des capacités facturées à l’usage.

Le coût dépend donc des opérations réellement exécutées, et pas simplement de l’étiquette « agent autonome ».

Work IQ natif et API Work IQ : une distinction importante

Pour comprendre la consommation, il faut distinguer l’utilisation de Work IQ intégrée à Microsoft 365 Copilot de l’utilisation de Work IQ comme service par une application ou un agent.

Dans Microsoft 365 Copilot, Work IQ fait partie de l’expérience proposée aux utilisateurs disposant de la licence appropriée.

Microsoft propose également des API et des outils Work IQ permettant à des applications et à des agents personnalisés d’exploiter cette intelligence.

Cette seconde approche relève d’un modèle de consommation en Copilot Credits.

Il faut également distinguer les Work IQ APIs des Microsoft 365 Copilot APIs. Même si les deux permettent aux développeurs de construire des expériences autour de Microsoft 365 et de Copilot, leurs usages, leurs prérequis et leurs modèles de consommation ne sont pas nécessairement identiques.

Quand des Copilot Credits peuvent-ils être consommés ?

Une consommation de Copilot Credits peut notamment intervenir lorsqu’un agent ou une application utilise des capacités facturées à l’usage.

Cela peut concerner :

  • un agent Copilot Studio utilisant Work IQ avec le GitHub Copilot harness ;
  • une application ou un agent appelant les API Work IQ ;
  • certains usages d’agents par des utilisateurs ne disposant pas d’une licence Microsoft 365 Copilot ;
  • certaines capacités avancées de Copilot Studio ;
  • certaines fonctions ou certains modèles d’AI Builder.

À l’inverse, l’utilisation de Microsoft 365 Copilot par un utilisateur disposant de la licence appropriée couvre les expériences incluses dans cette licence.

Il ne faut donc pas raisonner en considérant qu’une question posée à Copilot correspond systématiquement à un nombre fixe de Copilot Credits.

La consommation dépend de l’expérience utilisée, du runtime, des modèles, des outils appelés et des opérations réalisées.

Pourquoi deux agents similaires peuvent-ils coûter différemment ?

Prenons deux agents capables de répondre à une question sur une procédure commerciale stockée dans SharePoint.

Le premier est créé avec Agent Builder et utilisé dans Microsoft Copilot par un collaborateur disposant d’une licence Microsoft 365 Copilot. Son utilisation peut être couverte par cette licence selon les capacités utilisées.

Le second est créé dans Copilot Studio, utilise Work IQ dans une architecture facturée à la consommation et peut également appeler d’autres outils ou workflows. Son exécution peut donc consommer des Copilot Credits.

Pour l’utilisateur, les deux agents semblent simplement « chercher dans SharePoint ».

Derrière l’interface, ils peuvent pourtant utiliser des architectures, des runtimes, des outils et des modèles de consommation différents.

Le piège à éviter

L’erreur serait de déterminer le coût d’un agent uniquement à partir de son nom ou de l’endroit où il a été créé.

Avant la mise en production, vérifiez :

  • où l’agent est créé et exécuté ;
  • si ses utilisateurs disposent d’une licence Microsoft 365 Copilot ;
  • quelles sources de connaissances il utilise ;
  • quels outils et connecteurs sont activés ;
  • si Work IQ est utilisé ;
  • quel runtime Copilot Studio est utilisé ;
  • si les API Work IQ sont appelées ;
  • quelles fonctionnalités peuvent consommer des Copilot Credits ;
  • comment la consommation est supervisée ;
  • si les permissions Microsoft 365 et les accès aux applications métier sont correctement maîtrisés.

Cette analyse est particulièrement importante pour un agent exécutant de nombreuses opérations sans intervention humaine.

Quel choix faire ?

Il n’existe pas une architecture meilleure que les autres. Le choix dépend du besoin.

  • Agent Builder convient à la création rapide d’un agent déclaratif intégré à Microsoft Copilot.
  • Copilot Studio est plus adapté lorsqu’il faut ajouter des connecteurs, des workflows, des outils métier, davantage de contrôle ou plusieurs canaux.
  • Work IQ dans Copilot Studio devient pertinent lorsqu’un agent doit exploiter le contexte de travail provenant de plusieurs services Microsoft 365.
  • Les API et outils Work IQ répondent aux besoins d’intégration de cette intelligence dans une application ou un agent personnalisé.
  • Une architecture autonome est pertinente lorsqu’un processus doit progresser avec moins d’intervention humaine, à condition de maîtriser les outils, les autorisations et la consommation.

À retenir

Work IQ n’est ni une base de données, ni un connecteur, ni un nouveau nom pour Microsoft Graph.

C’est la couche d’intelligence qui permet à Microsoft 365 Copilot et aux agents de mieux comprendre le contexte du travail et d’exploiter les informations et outils auxquels ils sont autorisés à accéder.

Deux agents peuvent donc offrir une expérience très similaire tout en reposant sur des architectures et des modèles de consommation différents.

Avant de choisir une architecture, posez quatre questions : où l’agent sera-t-il exécuté, quelles données utilisera-t-il, quels outils appellera-t-il et quel modèle de licence ou de consommation s’appliquera ?
