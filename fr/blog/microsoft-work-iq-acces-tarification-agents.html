Microsoft Work IQ : comprendre son fonctionnement, ses accès et sa tarification

Work IQ est la couche d’intelligence qui alimente Microsoft 365 Copilot. Découvrez ses composants, les différentes façons dont les agents peuvent y accéder et les cas dans lesquels des Credits peuvent être consommés.

Microsoft 365Par Équipe MC3 Cloud27 octobre 2026

Microsoft présente Work IQ comme la couche d’intelligence qui permet à Copilot et aux agents de comprendre les contenus, les autorisations et le contexte de travail d’une organisation. Work IQ n’est pas un produit unique ni une simple base de données. Il combine la recherche de connaissances, l’ancrage tenant compte des autorisations, le contrôle des accès des agents et la mesure de la consommation.

Pour les clients et les partenaires, la question n’est donc pas seulement de savoir ce que Work IQ peut faire, mais aussi comment un agent y accède. Ce choix d’architecture influence les fonctionnalités, la gouvernance et les coûts.

Work IQ expliqué simplement

Work IQ peut être présenté sous la forme de huit composants complémentaires.

  1. Index sémantique : organise les contenus Microsoft 365 afin de retrouver une information par son sens, et pas uniquement à partir de mots-clés exacts.
  2. Ancrage tenant compte des autorisations : restitue uniquement les informations auxquelles l’utilisateur qui effectue la demande est déjà autorisé à accéder.
  3. Contexte : recherche, évalue et assemble les informations nécessaires pour construire une réponse fondée sur les données de l’organisation.
  4. API Work IQ : fournit un point d’entrée direct aux applications et aux agents situés en dehors de l’expérience Copilot native.
  5. Moteur de stratégies : contrôle chaque requête en fonction de l’identité, des autorisations et des règles administratives. Les opérations d’écriture sont désactivées par défaut.
  6. Outils : exposent des actions courantes, comme récupérer, créer ou mettre à jour des informations, à travers un vocabulaire cohérent.
  7. Espaces de travail : donnent aux agents exécutant des tâches longues un emplacement dans le tenant du client pour conserver leur travail entre plusieurs étapes.
  8. Facturation à l’usage : mesure les appels et les activités de recherche lorsque Work IQ est consommé dans un scénario d’agent facturable.

Les trois premiers composants constituent la capacité de recherche déjà utilisée par Copilot. Les cinq autres rendent cette capacité accessible à davantage d’agents et d’applications, tout en ajoutant des mécanismes de contrôle et de facturation.

Le mode d’accès détermine l’expérience

Les mêmes connaissances organisationnelles peuvent être exploitées depuis plusieurs environnements de création d’agents. Ces environnements ne doivent pas être considérés comme équivalents.

Agent Builder

Agent Builder fonctionne directement dans Microsoft 365 Copilot. Il convient aux assistants de questions-réponses simples destinés à une personne ou à une petite équipe.

L’agent accède nativement à Work IQ. Cette expérience est incluse dans la licence Microsoft 365 Copilot, mais Agent Builder n’expose pas les capacités étendues d’action et d’orchestration disponibles dans Copilot Studio.

Agents dans Copilot Chat

Des agents peuvent enrichir Microsoft 365 Copilot Chat avec les connaissances de l’entreprise. Microsoft prend en charge l’interaction et la planification reste proche de l’expérience Copilot Chat.

Pour les utilisateurs disposant d’une licence et utilisant les canaux Microsoft, la consommation peut relever du modèle d’usage raisonnable applicable. L’utilisation par des utilisateurs non licenciés peut consommer des Copilot Credits.

Agents Copilot Studio standards

Un agent Copilot Studio standard suit un processus défini à l’avance. L’accès aux services Microsoft 365 repose sur des capacités distinctes, comme les connecteurs et les serveurs MCP pour la messagerie, le calendrier, Teams, SharePoint, OneDrive ou d’autres services.

Dans ce modèle, Work IQ n’est pas automatiquement le chemin utilisé pour atteindre les données de l’organisation. Le concepteur de l’agent contrôle la séquence des actions et les sources appelées à chaque étape.

Agents autonomes dans un environnement GitHub Copilot

Dans l’environnement GitHub Copilot présenté dans les éléments transmis, l’agent détermine lui-même les étapes à exécuter au moment de la requête. Work IQ peut être ajouté comme outil facultatif afin de proposer un point d’entrée unique vers les connaissances de l’organisation.

Cette approche offre davantage de flexibilité, mais l’environnement consomme des crédits et l’utilisation de Work IQ est facturée séparément lorsque l’outil est appelé.

Accès direct par API

Les développeurs peuvent également appeler directement l’API Work IQ depuis leurs propres applications ou frameworks d’agents. Dans ce scénario, la consommation est mesurée indépendamment des licences Microsoft 365 Copilot déjà attribuées dans le tenant.

Qu’est-ce qui déclenche réellement une facturation Work IQ ?

La distinction principale se situe entre l’utilisation de Copilot et l’appel de l’API Work IQ.

D’après les éléments transmis, la création d’un agent Copilot Studio standard ne déclenche pas, à elle seule, le compteur Work IQ. L’ajout de capacités comme la messagerie, le calendrier ou Teams à travers leurs outils dédiés ne le déclenche pas automatiquement non plus.

La facturation Work IQ commence lorsque l’agent appelle l’API Work IQ, directement ou depuis un environnement dans lequel l’outil Work IQ a été activé.

Les informations tarifaires transmises distinguent deux composantes :

  • Outils : 0,1 Copilot Credit par appel, à tarif fixe.
  • Chat et contexte : consommation variable, sans tarif unitaire publié dans les éléments transmis.

Cette seconde composante constitue la principale difficulté de prévision. Sans tarif publié pour l’activité de recherche, une organisation ne peut pas estimer précisément le coût total d’un agent autonome à fort volume en se basant uniquement sur le prix des appels d’outils.

Deux compteurs nécessitent deux mécanismes de contrôle

La consommation de Copilot Studio et celle de Work IQ doivent être traitées comme deux postes distincts.

Les Copilot Credits de Copilot Studio sont administrés depuis l’environnement Power Platform. Work IQ nécessite sa propre politique de dépenses dans l’environnement d’administration Microsoft 365. Limiter un compteur ne limite pas automatiquement l’autre.

Avant un déploiement en production, le partenaire doit donc vérifier les deux contrôles suivants :

  • le budget de crédits attribué à l’agent ou à l’environnement ;
  • la politique de dépenses appliquée à la consommation de l’API Work IQ.

Ce point est particulièrement important pour les agents autonomes. Un utilisateur pose un nombre limité de questions pendant sa journée de travail. Un processus sans surveillance peut, lui, générer des requêtes en continu, ce qui change complètement l’économie de la solution.

Les points de gouvernance à expliquer avant le déploiement

Work IQ peut rechercher des informations en fonction de l’identité utilisée et des autorisations déjà présentes dans Microsoft 365. Cela ne supprime pas le besoin de gouvernance.

Trois contrôles méritent une attention particulière :

  • Accès en écriture : la création, la modification et la suppression sont désactivées par défaut et doivent être activées par un administrateur.
  • Limites du tenant : les appels sont associés à un tenant et à une identité authentifiée. Ils ne s’exécutent pas de manière anonyme.
  • Qualité des autorisations : la recherche tenant compte des permissions reflète le modèle d’accès déjà configuré. Des droits trop larges dans SharePoint, Teams ou les fichiers resteront des droits trop larges.

Work IQ doit donc être introduit avec une revue des identités, des accès aux données et des politiques de dépenses des agents, et non comme une simple fonctionnalité d’intelligence artificielle isolée.

Comment orienter un client

Le choix doit partir du modèle d’usage plutôt que du nom de la technologie.

  • Choisissez Agent Builder pour créer un assistant de connaissance simple dans Microsoft 365 Copilot.
  • Choisissez Copilot Chat pour enrichir l’expérience conversationnelle Microsoft avec les connaissances de l’entreprise.
  • Choisissez un agent Copilot Studio standard lorsque le processus peut être défini précisément et que chaque action doit être contrôlée à l’avance.
  • Choisissez un environnement autonome associé à Work IQ lorsque l’agent doit décider dynamiquement des recherches et des étapes à exécuter.
  • Choisissez l’accès direct par API lorsque Work IQ doit être intégré à une application personnalisée ou à un framework d’agents externe.

Plus le client demande d’autonomie et de flexibilité, plus le contrôle des coûts, des autorisations et de l’audit devient important.

Le point essentiel à retenir

Work IQ est une même capacité d’intelligence accessible par plusieurs portes. Le modèle de connaissances et d’autorisations peut être commun, mais le modèle commercial ne l’est pas.

Avant de positionner un agent, il faut confirmer trois éléments : l’environnement dans lequel il sera construit, la manière dont il accédera aux données Microsoft 365 et le compteur de consommation qui s’appliquera. C’est ce qui distingue une preuve de concept utile d’un service de production avec une gouvernance et des coûts maîtrisés.
